Software Architecture Monday - Complete Lessons

218+ video lessons from Mark Richards covering all aspects of software architecture. Organized by topic.

1. Getting Started with Architecture (Lessons 1-18)

  • Lesson 1 - Event-Driven Architecture: Request/Reply Processing
    How to implement synchronous request/reply within async messaging using correlation IDs and reply queues. Patterns for handling responses in event-driven systems.
  • Lesson 2 - How Kafka Differs From Standard Messaging
    Kafka's log-based architecture vs traditional message queues. Append-only logs, replay capability, partitions, consumer groups.
  • Lesson 3 - Soft Skills: Gaining Technical Breadth
    The 20-minute rule: Spend 20 minutes daily learning something new outside your expertise area. Building T-shaped skills.
  • Lesson 4 - Microservices: Distributed Logging
    Correlation IDs across service boundaries to trace requests. Header propagation, distributed tracing tools.
  • Lesson 5 - Microservices: Reducing Staging Iterations
    Shift-left testing: catch issues earlier in the development cycle. Local development, feature flags, canary releases.
  • Lesson 6 - Classifying Architecture Patterns
    Distinguish between: patterns (solver-specific solutions), styles (broad structural categories), architecture patterns (structural solutions to recurring problems).
  • Lesson 7 - Analyzing Architecture: Structural Decay
    Entropy in codebases: how technical debt accumulates and accelerates. Signs of structural decay and how to prevent it.
  • Lesson 8 - Analyzing Architecture: Components
    First step in architecture: identify what components make up your system. Component identification techniques.
  • Lesson 9 - Analyzing Architecture: Macro Techniques
    Architectural Analysis at Scale: ATAM (Architecture Tradeoff Analysis Method), CBAM (Cost Benefit Analysis Method).
  • Lesson 10 - Analyzing Architecture: Microservices
    Key metrics for microservices: service span, cyclic dependencies, modularity measurements. Analyzing service boundaries.
  • Lesson 11 - Analyzing Architecture: Code Metrics
    Use code metrics (Lines of Code, cyclomatic complexity, coupling) to analyze architecture health.
  • Lesson 12 - CQRS and Microservices
    Command Query Responsibility Segregation: separate read/write models. Benefits for scaling reads vs writes independently.
  • Lesson 13 - Microservices and Reporting
    Challenge: microservices fragment data making reporting difficult. Solutions: event sourcing, data warehouse, CDC (Change Data Capture).
  • Lesson 14 - Refactoring Patterns: Migration vs. Adaptation
    Two approaches to refactoring: Strangler Fig pattern (gradual migration) vs. Adaptation (in-place changes).
  • Lesson 15 - Refactoring: Business Justification
    How to justify refactoring to business: cost of delay, technical debt interest, opportunity cost.
  • Lesson 16 - The Challenges of Architecture Teams
    Common challenges: politics, coordination, communication gaps between architecture and development teams.
  • Lesson 17 - Architecture Tradeoffs
    Every architecture decision involves tradeoffs. How to analyze and communicate tradeoffs effectively.
  • Lesson 18 - The Fallacies of Distributed Computing
    The 8 fallacies: Network is reliable, Latency is zero, Bandwidth is infinite, Network is secure, Topology doesn't change, One administrator, Transport cost is zero, Network is homogeneous. These cause most distributed system failures.

2. Integration Architecture (Lessons 19-40)

  • Lesson 19 - File Transfer Integration
    Integration style: batch file exchange between systems. Use cases, benefits, drawbacks.
  • Lesson 20 - Shared Database Integration
    Tight coupling via shared database. Avoid unless necessary. Creates brittle dependencies.
  • Lesson 21 - Remote Procedure Invocation
    Synchronous coupling: REST, gRPC, SOAP. Tight but simple. Call latency considerations.
  • Lesson 22 - Messaging Integration
    Asynchronous, loose coupling via message queues. Benefits of temporal decoupling.
  • Lesson 23 - Orchestration vs. Choreography
    Orchestration: central coordinator tells services what to do. Choreography: services react to events. Tradeoffs.
  • Lesson 24 - Lean Modeling Concepts
    Domain-Driven Design: bounded contexts, core domain, generic subdomains, supporting subdomains.
  • Lesson 25 - Architectural Abstraction
    Abstraction levels: domain (business logic), technical (frameworks), deployment (infrastructure).
  • Lesson 26 - Agile Architecture Review Boards
    Lightweight architecture reviews in agile teams. Just enough governance.
  • Lesson 27 - Circuit Breaker Pattern
    States: Closed (normal), Open (failures detected), Half-Open (testing recovery). Prevents cascading failures.
  • Lesson 28 - Service Design Patterns
    Patterns: Naked Service (exposes internals), Facade Service (simplified interface), Anti-Corruption Layer.
  • Lesson 29 - Component and Service Coupling
    Coupling types: Stamp (shares schema), Common (shares state), Content (direct access). Minimize coupling.
  • Lesson 30 - Agile and Architecture
    Architecture in agile: just enough, just in time. Avoid big upfront design.
  • Lesson 31 - Presenting Architecture
    Architecture presentations: know your audience, focus on business value, tell a story.
  • Lesson 32 - Diagramming Architecture
    C4 model: Context (system), Container (apps), Component (modules), Code (classes). Four levels of abstraction.
  • Lesson 33 - Creating a Service Taxonomy
    Service types: Business Capability Service (core logic), Entity Service (data), Utility Service (cross-cutting).
  • Lesson 34 - Creating Service Domains
    Group related services into domains for ownership and boundaries. Domain-driven boundaries.
  • Lesson 35 - Watch Notification Pattern
    Real-time monitoring via event subscription. Detect anomalies early.
  • Lesson 36 - Embedded Messaging
    Embed message broker within application for simpler deployment. Tradeoffs vs standalone brokers.
  • Lesson 37 - Translating Quality Attributes to Business
    Translate technical -ilities (scalability, performance) to business value for stakeholders.
  • Lesson 38 - Identifying Microservices
    Methods: Decompose by business capability, DDD bounded contexts, self-discovering services.
  • Lesson 39 - Integration Hubs (ESBs)
    Enterprise Service Buses: benefits and pitfalls. Consider lightweight alternatives.
  • Lesson 40 - Common Integration Patterns
    Patterns: Point-to-Point, Publish/Subscribe, Hub-and-Spoke.
