Lesson 53: Distributed Transactions Using Sagas

Watch Video Lesson | March 18, 2019

Video Summary

Sagas replace traditional 2PC for distributed transactions. Instead of locking resources, use compensating transactions to undo steps if any step fails.

Two Approaches:

  1. Choreography - Services emit and listen to events
    Pros: Loose coupling, no central point
    Cons: Hard to trace, implicit flow
  2. Orchestration - Central coordinator manages the flow
    Pros: Clear ownership, easier debugging
    Cons: Central point of failure, tight coupling

Example: Order Processing Saga

Order Service: Create Order (pending)
    → Payment Service: Reserve Payment
    → Inventory Service: Reserve Items
    → Shipping Service: Create Shipment
    
If any step fails:
    → Compensate in reverse order
    → Refund payment, release inventory, cancel shipment
