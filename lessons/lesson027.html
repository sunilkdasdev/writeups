Lesson 27: Circuit Breaker Pattern

Watch Video Lesson | July 23, 2018

Video Summary

The Circuit Breaker Pattern prevents cascading failures in distributed systems by detecting failures and stopping requests to failing services.

Three States:

  1. Closed - Requests flow normally. Counter tracks failures.
  2. Open - Failures threshold reached. Requests fail immediately.
  3. Half-Open - Testing recovery. Limited requests allowed.

When to Use:

  • External API calls
  • Database connections
  • Remote service communication
  • Any network-dependent operation

Implementation Examples

Resilience4j (Java)

CircuitBreakerConfig config = CircuitBreakerConfig.custom()
    .failureRateThreshold(50)
    .waitDurationInOpenState(Duration.ofSeconds(10))
    .slidingWindowSize(10)
    .build();

CircuitBreaker circuitBreaker = CircuitBreaker.of("myService", config);

Configuration Parameters

  • failureRateThreshold - % failures to open (default: 50)
  • waitDurationInOpenState - Time before half-open (default: 60s)
  • slidingWindowSize - Number of calls to track
  • permittedNumberOfCallsInHalfOpenState - Test requests allowed
