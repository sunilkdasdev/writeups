Lesson Summaries - Software Architecture Monday

200+ video lessons. Key takeaways summarized below.

Getting Started (Lessons 1-10)

  • Lesson 1 - Event-Driven Architecture: Request/Reply Processing
    How to implement synchronous request/reply within async messaging systems using correlation IDs and reply queues.
  • Lesson 2 - How Kafka Differs From Standard Messaging
    Kafka's log-based architecture vs traditional message queues; append-only logs, replay capability.
  • Lesson 3 - Gaining Technical Breadth
    The 20-minute rule: Spend 20 minutes daily learning something new outside your expertise.
  • Lesson 4 - Distributed Logging
    Correlation IDs across service boundaries to trace requests across distributed systems.
  • Lesson 5 - Reducing Staging Iterations
    Shift-left testing; catch issues earlier in the development cycle.
  • Lesson 6 - Classifying Architecture Patterns
    Distinguish between patterns (solver-specific), styles (broad categories), and architecture patterns (structural solutions).
  • Lesson 7 - Structural Decay
    Entropy in codebases; how technical debt accumulates and accelerates.
  • Lesson 8 - Component Identification
    First step in architecture: identify what components make up your system.
  • Lesson 9 - Macro Techniques
    Architectural analysis at scale: ATAM, CBAM methods.
  • Lesson 10 - Analyzing Microservices
    Key metrics: service span, cyclic dependencies, modularity measurements.

Integration Architecture (Lessons 11-22)

  • Lesson 11 - Code Metrics
    Use code metrics (LOC, cyclomatic complexity, coupling) to analyze architecture.
  • Lesson 12 - CQRS and Microservices
    Command Query Responsibility Segregation: separate read/write models for scaling.
  • Lesson 13 - Microservices and Reporting
    Challenge: microservices fragment data; solutions include event sourcing, data warehouse.
  • Lesson 19 - File Transfer Integration
    Integration style: batch file exchange between systems.
  • Lesson 20 - Shared Database Integration
    Tight coupling via shared database; avoid unless necessary.
  • Lesson 21 - Remote Procedure Invocation
    Sync coupling: REST, gRPC, SOAP; tight but simple.
  • Lesson 22 - Messaging Integration
    Async, loose coupling via message queues.

Event-Driven Architecture (Lessons 23-35)

  • Lesson 23 - Orchestration vs. Choreography
    Orchestration: central coordinator tells what to do. Choreography: services react to events.
    Choreography is more resilient; orchestration is more controllable.
  • Lesson 24 - Lean Modeling Concepts
    DDD: bounded contexts, core domain, generic subdomains.
  • Lesson 25 - Architectural Abstraction
    Abstraction levels: domain, technical, deployment.
  • Lesson 26 - Agile Architecture Review Boards
    Lightweight architecture reviews in agile teams.
  • Lesson 27 - Circuit Breaker Pattern
    States: Closed (normal), Open (failures detected), Half-Open (testing recovery).
    Prevents cascading failures.
  • Lesson 28 - Service Design Patterns
    Patterns: naked service (exposes internals), facade service (simplified interface).
  • Lesson 29 - Coupling Types
    Stamp coupling (shares schema), common coupling (shares state), content coupling (direct access).
  • Lesson 30 - Agile and Architecture
    Architecture in agile: just enough, just in time.
  • Lesson 31 - Presenting Architecture
    Architecture presentations: know your audience, focus on value.
  • Lesson 32 - Diagramming Architecture
    C4 model: Context, Container, Component, Code levels.
  • Lesson 33 - Service Taxonomy
    Service types: business capability, entity service, utility service.
  • Lesson 34 - Service Domains
    Group related services into domains for ownership and boundaries.
  • Lesson 35 - Watch Notification Pattern
    Real-time monitoring via event subscription.
